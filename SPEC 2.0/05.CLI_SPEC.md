# 📟 LOADSTAR 2.0 — CLI Spec

## 1. 실행 모델

`loadstar_ui` 실행 파일 하나가 GUI와 CLI를 겸한다.

- **인자 없이 실행**: GUI(Wails 앱)가 뜬다.
- **서브커맨드 지정**: 아래 명령어들이 CLI 모드로 동작한다.

## 2. 명령어

### `loadstar create <FORMAT> "이름"`

- `FORMAT`: `wp` | `dwp` | `group`
- `[FORMAT][VER][DATE]이름.md` 파일명을 생성하고(`02.ELEMENT_FORMAT.md §2`), 동명 충돌을 확인한 뒤(`02.ELEMENT_FORMAT.md §5`) 해당 FORMAT 폴더(`.loadstar/<FORMAT>/`)에 배치한다.
- 부록(`appendix/WP.md`, `appendix/DWP.md`, `appendix/GROUP.md`)의 포맷을 기준으로 초기 본문을 스캐폴딩한다.

### `loadstar todo [all|standby|active|done|...]`

- 온디맨드 도메인 조회기(③, `04.META_EXTRACTION.md §7`)를 통해 그때그때 WP의 TODO/STATUS를 계산해 필터링 출력한다. DB에 캐싱된 상태를 읽는 것이 아니라 매번 md를 다시 읽어 계산한다.
- 옵션은 STATUS 코드에 대응한다: `standby`=`S_IDL`, `active`=`S_PRG`, `done`=`S_STB`. `all`은 필터 없이 전체.

### `loadstar show`

- STATUS별 분포, 이슈 있는 문서 개수 등 프로젝트 현황을 요약해 보여준다.
- `01.MASTER_GUIDE.md §6`("세션 진입은 SQLite를 거친다")의 실행 창구다 — AI/사람이 작업 시작 전 가장 먼저 실행하는 명령.

### `loadstar issues`

- 프로젝트 전체 WP/DWP의 `ISSUE` 내용을 훑어 나열한다.
- `01.MASTER_GUIDE.md §4.1`에 남겨둔 향후 과제(작업 착수 시점에 미해결 이슈를 능동적으로 조회하는 구조)의 최소 구현체다.

### `loadstar validate [경로]`

- `CONNECTIONS`(PARENT/REFERENCE/ITEMS)와 FLOW의 `REFERENCES`가 가리키는 파일이 실제로 있는지, 같은 FORMAT 안에서 표시 이름이 겹치지 않는지 검사한다.
- FLOW는 추가로: `REFERENCES`에만 있고 그림에는 없는 노드, 같은 노드를 두 번 가리키는 항목, FLOW끼리의 참조 순환.
- **어긋남을 찾아도 종료 코드는 0이다.** SPEC이 완전한 일관성을 목표로 하지 않으므로(`01.MASTER_GUIDE.md §3`) 드리프트는 실패가 아니라 보고 대상이다 — 이 명령은 어긋난 자리를 발견 가능하게 만드는 것이 역할이고, 막거나 고치지 않는다.
- 색인(`index.db`)이 아니라 md 원본을 직접 읽는다 — 재색인하지 않은 상태에서도 지금 디스크에 있는 그대로를 검사한다.
- `04.META_EXTRACTION.md §9` Validator의 CLI 진입점.

### `loadstar reindex`

- 구조 추출기(①)를 즉시 수동 실행해 SQLite(`nodes`/`edges`/`history`)를 재생성한다.
- 자동 트리거 방식(파일 변경 감지/git hook 등, `04.META_EXTRACTION.md §10` 미결 사항 1번)이 확정되기 전까지는 재색인의 유일한 수단이다.
