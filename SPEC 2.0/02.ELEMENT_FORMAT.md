# 📝 LOADSTAR Element Format — Common Rules

이 문서는 모든 요소(Element) 타입에 공통으로 적용되는 규칙을 정의한다. 특정 요소 타입(WP, DWP 등)의 구체적인 작성 규칙은 `appendix/` 하위 문서에 정의한다.

---

## 1. 요소(Element)란

LOADSTAR의 모든 작업 단위·데이터 정의는 "요소"로 표현되며, 요소는 `[FORMAT][VER][DATE]이름.md` 형식의 md 파일 하나로 존재한다. `FORMAT`은 요소의 종류를 나타내며, 종류별 구체적 작성 규칙은 부록에서 정의한다.

이 명명 규칙을 따르지 않는 md 파일은 요소로 취급하지 않는다 — **형식 없는 일반 파일**로 간주하며, 구조 추출기(①)의 구조적 파싱 대상에서 제외한다. 자유 형식 문서(중간 점검 메모, 리서치 노트 등)는 이 규칙 덕분에 아무 제약 없이 프로젝트 어디에나 둘 수 있다.

**유일한 예외 — `OTHER`**: 형식 없는 일반 파일 중 GROUP으로 조직화하고 싶은 것은 `.loadstar/OTHER/` 아래로 옮기면 정식 카탈로그 요소(§7)가 된다. 이때도 `[FORMAT][VER][DATE]이름.md` 이름 규칙은 따르지 않는다 — `.loadstar/OTHER/`에 있다는 물리적 위치 자체가 유일한 신원·타입 판별 기준이다(자세한 내용은 `appendix/OTHER.md`).

## 2. 파일 명명 규칙

```
[FORMAT][VER][DATE]이름.md
```

구조화된 필드(`[FORMAT][VER][DATE]`)를 앞에 연속으로 몰아두고, 자유 텍스트인 `이름`은 마지막 `]` 뒤부터 `.md` 앞까지로 정의를 고정한다. 이렇게 하면 `이름`에 어떤 문자가 들어가도(대괄호 포함) 파싱 경계가 흔들리지 않는다 — `이름`이 두 구조화 필드 사이에 끼어 있던 이전 방식보다 견고하다.

| 필드 | 의미 | 비고 |
|:--|:--|:--|
| `FORMAT` | 요소 타입 | 부록 문서 하나당 하나의 FORMAT을 정의한다 |
| `VER` | 이 파일이 따르는 포맷 스키마 버전 | 콘텐츠를 수정해도 바뀌지 않는다. 같은 파일을 계속 고치며 git이 변경 이력을 담당한다(콘텐츠 리비전 번호가 아니다) |
| `DATE` | `YYYY.MM.DD` | 생성일, 불변 |
| `이름` | 사람이 읽는 라벨 | 자유롭게 리네이밍 가능. 공백·한글 등 자유 텍스트 허용. 대괄호(`[`/`]`)까지 포함해도 파싱에 영향 없음 |

예: `[WP][2.0][2026.07.25]초기화 작업.md`

## 3. 신원 원칙

파일명이 유일한 신원 정보다. 파일 내부에 별도 식별 라인(주소, 버전, 생성일 등)을 중복 기재하지 않는다.

## 4. 참조 방식

요소 간 참조(CONNECTIONS 등)는 대상 파일명 문자열을 그대로 사용한다. `FORMAT` 접두어로 대상이 속한 타입 폴더를 추론한다 — 단, 참조된 파일명이 `[FORMAT][VER][DATE]이름.md` 패턴에 맞지 않으면 `OTHER`로 간주하고 `.loadstar/OTHER/`에서 찾는다(§1 유일한 예외).

**참조 무결성**: 리네이밍으로 참조가 깨질 수 있다. 검증 패스가 깨진 참조를 검출해 인지 가능한 상태로 만든다 — 리네이밍 자체를 막지 않는다(§3 Tolerable Consistency 원칙).

## 5. 동명 충돌

같은 FORMAT 폴더 내 파일명이 겹치지 않도록 생성 시점에 대상 폴더를 확인한다.

## 6. 공통 구조 (Envelope)

모든 요소는 최소한 다음을 포함한다:

- **IDENTITY**: `SUMMARY`(필수) 등 요소 정체성
- **CONNECTIONS**: `PARENT`, `REFERENCE` 등 관계 정보

다음은 필요한 타입에서만 사용하는 선택적 공통 슬롯이다:

- **ATTACHMENTS**: 그래프 외부 자료(`https://`, `file:///`)를 1급으로 매단다
- **ISSUE**: 설계 시점 제약, 미결정·미해결 사항 — 자유 형식 텍스트
- **COMMENT**: 자유 형식 코멘트

**`OTHER`는 공통 봉투 자체가 면제된다** — IDENTITY/CONNECTIONS도 요구하지 않는다. 완전히 자유 형식 콘텐츠를 위한 자리이기 때문이다(`appendix/OTHER.md`).

> **CODE_MAP 제거됨(2026-07-27)** — 실제 활용도가 불명확해 제거. 코드 탐색 범위 안내가 다시 필요해지면 재검토.

타입 고유 슬롯(예: WP의 `STATUS`/`GOAL`/`TODO`, DWP의 `TABLES`)은 각 부록에서 정의한다.

## 7. 요소 카탈로그

| FORMAT | 설명 | 정의 문서 |
|:--|:--|:--|
| `WP` | 작업 실행 단위 | `appendix/WP.md` |
| `DWP` | 데이터의 개념적 정의 | `appendix/DWP.md` |
| `GROUP` | 선택적 조직화 컨테이너 (카테고리 묶음) | `appendix/GROUP.md` |
| `OTHER` | 어디에도 속하지 않는 자유 형식 md 파일 — GROUP으로 조직화할 수 있도록 물리적으로 편입 | `appendix/OTHER.md` |
| `FLOW` | 업무·처리 흐름 기술 (mermaid 그림 + 노드별 요소 참조) | `appendix/FLOW.md` |

새 요소 타입을 추가할 때는 이 표에 행을 추가하고 `appendix/`에 정의 문서를 작성한다. 본 문서(공통 규칙)는 새 타입 추가로 인해 수정될 필요가 없다.

## 8. 물리 저장 경로

```
.loadstar/
├── WP/
├── DWP/
├── GROUP/
├── OTHER/
├── FLOW/
```

- `FORMAT` 값이 곧 폴더명이다 (예: `WP` 파일 → `.loadstar/WP/`). v1처럼 별도 접두어→폴더명 매핑 표를 두지 않는다.
- 새 FORMAT을 추가하면 같은 이름의 폴더가 새로 생긴다.

### 추출기 SQLite 파일

- 위치: `.loadstar/.cache/index.db`
- **git에 커밋하지 않는다** — md 파일(원본)로부터 구조 추출기가 언제든 재생성할 수 있는 파생 캐시이기 때문. 프로젝트의 `.gitignore`에 `.loadstar/.cache/`를 등록한다.
